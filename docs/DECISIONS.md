# Decisions

The choices that would otherwise look arbitrary — and would get "simplified"
back into bugs. Each links to the commit that made it.

---

### Expenses are stored on device only

`7cc723f` · [#1](../../issues/1)

SwiftData, local store, no account. No server to run, no data leaving the
phone, no privacy policy to write. Costs multi-device sync, which is
[#17](../../issues/17) and blocked on the Apple account.

### Categories are stored as raw strings, not enum ordinals

`6d70112` · [#13](../../issues/13)

Ordinals would silently re-map every expense when the enum is reordered.
Strings survive reordering, and `ExpenseCategory.stored()` maps retired
values onto their nearest replacement **on read** without rewriting the
store.

This paid for itself: when the category list was replaced, `groceries` was
mapped to Takeaways; when Groceries was added back a commit later, those
expenses returned to Groceries on their own, because nothing had overwritten
them.

### The right-most separator is the decimal point only when 1–2 digits follow

`a829019` · [#5](../../issues/5)

The decimal key is `,` in South Africa and `.` elsewhere. Treating `,` as a
thousands separator stored `45,50` as **R4550**.

The rule makes `45,50` and `45.50` both 45.50, while `1,234` stays 1234.
Covered by `MoneyTests`.

### CSV exports plain numbers, not formatted Rand

`3d564cf` · [#11](../../issues/11)

Deliberately *not* how the app displays amounts. `R1,234.56` imports into
Numbers and Excel as **text**, which cannot be summed. The export is for
machines; the display is for people.

### CSV is handed over as a file, not as data

`621ed96` · [#12](../../issues/12)

`DataRepresentation` gives the system raw bytes. Share extensions that attach
a document want a file on disk, so most refused to appear at all.
`FileRepresentation` writes a temp file and passes the URL, still lazily.

### `SpinningCoin` conforms to `Animatable`

`4398684` · [#9](../../issues/9)

Without it, reading the `@State` angle returns the *final* value for the
whole animation, and the R renders mirrored through half of every turn.
`Animatable` re-evaluates `body` at each step with the real interpolated
angle.

**Remove this conformance and the bug comes back.**

### EAN-13 is implemented by hand

`d12f957` · [#14](../../issues/14)

Core Image generates Code 128, QR, Aztec and PDF417 — but not EAN-13, which
is what most retail loyalty cards use. Rendering those digits as Code 128
produces a barcode the till misreads or rejects.

Drawn as vector bars, not a bitmap: a scaled bitmap blurs at the module edges
and scans badly. The 9- and 7-module quiet zones are mandatory; without them
scanners refuse to read.

Verified by encoding and decoding back through an independent decoder.

### `ExpenseCategory` and friends are `nonisolated`

`b051310`

The target compiles with `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`, and
SwiftData models are nonisolated, so a MainActor enum cannot be read from
one. Removing `nonisolated` fails the build rather than misbehaving at
runtime, which is the good kind of failure.

### The splash is a view, not a launch screen

`4398684`, `2b4be14` · [#8](../../issues/8)

iOS launch screens cannot animate — the system draws them before any app code
runs. `UILaunchScreen` is therefore a flat colour matching the splash, and
`SplashView` animates over the top once the app is up.

Since the local store opens instantly, the animation is deliberate delay, not
cover for work. It is tap-to-skip, plays once per install, and reduces to a
fade under Reduce Motion.

### The app icon is generated by a script

`d45459b` · [#7](../../issues/7)

Nothing on the build machine converts SVG, and committing a hand-exported
bitmap would leave the real source nowhere. `Tools/GenerateAppIcon.swift`
draws it with Core Graphics and writes the PNGs into the asset catalog.

### iCloud sync sits behind a compile flag, not a runtime check

`7b3dc9b` · [#17](../../issues/17)

CloudKit does not fail politely. Request a CloudKit container without the
entitlement and the app **launches and dies** — and because the failure is
asynchronous inside CloudKit, `try?` around `ModelContainer` never sees it.

A runtime fallback cannot work here, so the decision is made at compile time
with `ZAKA_CLOUDKIT`.

### Tests live in a Swift package, not an Xcode test target

`this commit` · [#20](../../issues/20)

Adding a test target means hand-editing `project.pbxproj`, which is fiddly
and easy to break. A package compiles the app's own `EAN13.swift` and
`Money.swift` directly — one source of truth, no copy to drift — and runs
anywhere with `swift test`.

The cost is that only pure logic is covered. Views, SwiftData and the CSV
export are still untested.
